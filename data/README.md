Automatically acquired public Sentinel-1 RTC river-corridor GeoTIFFs, original STAC item metadata, and the local SQLite product catalog are stored here at runtime and excluded from Git. The app reads COG windows from Microsoft Planetary Computer using its read-only SAS token API; only the clipped VV corridor is retained locally.

The product catalog preserves item IDs, acquisition timestamps, footprints, orbit, polarization, source asset URL, license, centerline coverage, processing status, and errors. Signed access tokens are used in memory only and are never saved.

NISAR discovery is automatic through ASF DAAC. Set `EARTHDATA_TOKEN` in the process environment or in the ignored repository-root `.env` file to let the supported `asf_search` client authenticate and download a cataloged GCOV HDF5 product. Downloaded files are size-checked, opened with `h5py`, and registered with their source metadata. The separate GCOV processor reads frequency-A `HHHH`/`HVHV` and the product validity mask in windows, uses projected coordinate axes and CRS, and writes its dual-band measurement GeoTIFF, candidate mask GeoTIFF, display GeoJSON, and processing metadata beside the HDF5 file in `data/acquisitions/<river>/<product>/nisar-processing/` only when paired valid corridor pixels exist. Otherwise, it records no-data metadata and creates no mask or area result. Candidate masks are unvalidated classifications, not verified river boundaries or change results. Frequency B and other NISAR product types are not processed. Without a usable token, the app reports the access restriction and continues with public Sentinel-1 RTC data. The app does not register accounts, bypass access controls, or fabricate acquisitions.

To register an explicitly selected ASF NISAR L2 GCOV granule without downloading it, send `POST /api/acquisitions/nisar/metadata` with JSON `{"river_id":"tungabhadra","product_id":"<exact ASF product ID>"}`. This performs one ASF metadata lookup, validates the product identity and NISAR L2 GCOV metadata, and checks whether its footprint overlaps the selected river's existing 1,500 m buffered centerline corridor. A positive corridor-area coverage percentage is reported, but coverage sufficiency is not assessed; it does not establish full study-AOI coverage. Duplicate registrations preserve existing download and processing state and local paths. Signed URL query parameters are not stored or returned. This endpoint does not require `EARTHDATA_TOKEN`, download HDF5 data, create acquisition jobs, or trigger automatic refresh.

ASF may omit `processingType` and may include checksum keys with null values. Registration leaves an absent processing type and absent checksum unset; an explicitly supplied processing type must be `L2`, and a supplied checksum must have a valid supported digest shape.

## A_009 output audit

The A_009 processor uses the frequency-A HH/HV inputs after confirming the product's `gamma0` normalization and `Linear power` expression metadata. It estimates independent Otsu thresholds using 900-bin histograms spanning -60 to +30 dB and selects pixels at or below both thresholds. No spatial speckle filter or component cleanup is applied. These are configurable-candidate outputs, not a validated water classifier.

The analytical mask is 25,660 × 21,962 pixels in EPSG:32643. A full-pixel audit found 9,024,198 class-0 pixels, 3,885,882 class-1 pixels, and 550,634,840 NoData pixels (255); no other values were present. The two-band measurement raster stores finite values for every class-0/class-1 pixel and NaN at every mask NoData pixel. The measurement, mask, polarization-comparison, and threshold-sensitivity rasters share dimensions, CRS, and geotransform. The display GeoJSON contains only the first 5,000 features and is marked truncated; use the complete GeoTIFF for analysis. Candidate counts and area are not reference-water measurements.

A_010 remains a separate product and was not downloaded. Kaveri is a separate pilot workflow.

The existing reviewed-reference workflow reports confusion-matrix, precision/recall/F1/IoU, coverage, and area-difference metrics with explicit limitations. Do not use the NDWI candidate as reference labels. Previously reported agreement/IoU between two automatic candidates are descriptive comparisons, not accuracy metrics.
