## Executive summary

SAR Sentinel India is a React/Vite dashboard backed by a FastAPI service. It provides Kaveri and Tungabhadra map views, satellite-catalog discovery, persistent acquisition/processing jobs, NISAR and Sentinel-1 product workflows, exploratory Sentinel-2 context, and deterministic analysis based on persisted product records.

The application has processed real satellite products into candidate classifications and preserves their validity and NoData information. These classifications have **not** been independently validated as water, riverbanks, or channel boundaries. No accuracy score, verified width, erosion/deposition result, or flood detection result is available. The project includes a validation workflow, but no independently reviewed reference labels or project validation scores currently exist.

The current checklist is **64/69 (92.8%)**. This percentage counts completed checklist items only; it is not a scientific-readiness or validation score. The unchecked items are intentionally retained where suitable evidence or inputs are missing.

## 1. Software implementation status

The feasible software work for the current local products and supported workflows is implemented and regression-checked:

- The existing Leaflet map displays independently selectable Kaveri and Tungabhadra centerlines and satellite/candidate layers. Legends identify visible layers and clarify partial coverage. Verified left/right bank geometries are unavailable and are not fabricated.
- FastAPI exposes the river, acquisition, processing, analysis, and validation workflows while preserving the original health, regions, and observations APIs.
- Acquisition and processing jobs persist in SQLite across restarts, expose lifecycle state and stages, avoid duplicate active operations for the same product/operation, and support eligible retries. NISAR and Sentinel-1 processing paths remain separate. Automatic scheduling is disabled by default.
- The NISAR GCOV processor uses the product's frequency-A HH/HV data and validity information, processes in windows, and preserves NoData. It reports no usable corridor data separately from failure.
- Sentinel-1 RTC candidate products remain distinct from NISAR products. Exact-grid Sentinel-1 pairs that pass processing-metadata checks can be compared through a separate user-triggered workflow; the outputs remain unvalidated candidate-water differences.
- Sentinel-2 NDWI outputs are selectable exploratory layers, preserve partial coverage/NoData, and display acquisition/support context. Candidate masks use NDWI > 0 and are not ground truth.
- The independent-validation workspace accepts bounded 0/1/255 GeoTIFF masks, aligns categorical references with nearest-neighbour resampling, and computes metrics only on common valid pixels when both reference classes are present. It records provenance supplied by the operator but cannot authenticate reviewer identity, prove label independence, or establish sampling quality.
- AI Analysis is deterministic, not an external LLM. It uses persisted catalog/product measurements for the selected river and product, displays provenance, makes stale selections explicit, and does not invent metrics for catalog discoveries without persisted processing records.
- Dashboard loading, error, empty, retry, layer visibility, and download states are covered by regression tests. Demonstration content remains visibly distinct from real catalog and product records.

## 4. Scientific limitations and outstanding evidence

The following work is **not complete**:

1. **Independent validation:** No independently reviewed, temporally suitable water/non-water reference labels are available. The inspected near-date Landsat sample was unsuitable for defensible manual water-boundary interpretation at its observed quality/resolution. No confusion matrix, precision, recall, F1, IoU, or accuracy score is claimed.
2. **Candidate cleanup or alternate classifier:** Component-size scenarios were tested and quantified but not validated as cleanup. No parameter or alternate classification method is empirically justified against independent labels. The original masks remain unchanged.
3. **Scientific interpretation of temporal comparisons:** Compatible Sentinel-1 candidate comparisons are available, but are unvalidated. Independent reference labels, accurate co-registration assessment, seasonal normalization, and evidence about threshold/preprocessing uncertainty are still missing. Only one processed NISAR candidate date is available; no NISAR temporal comparison is possible.
4. **Verified riverbanks and channel width:** OSM centerlines are mapped reference centerlines, not surveyed active-channel axes. Independent left/right bank geometries are unavailable. Automated axis-normal bank-to-bank width measurement remains deferred.
5. **Flood, erosion, deposition, and riverbank change:** These are not implemented as scientifically validated outputs and are not claimed.
6. **Reference provenance:** The validation service records user-submitted provenance but cannot independently authenticate the provider/reviewer or prove reference-label independence, quality, or sampling design.

The next scientifically defensible work requires suitable independently sourced and reviewed labels with acquisition-time and spatial support appropriate to the satellite products; co-registration and seasonal-normalization evidence before interpreting existing candidate differences; and trustworthy channel-axis/bank geometry for width work.
